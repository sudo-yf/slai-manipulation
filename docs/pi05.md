# PI0.5 training

The PI0.5 path keeps the capture dataset and the training view separate:

```text
LeRobot v3, 30 Hz, 26-DoF real contract
  -> validated episode-aware downsampling
  -> LeRobot v2.1, 15 Hz, 224x224 RGB
  -> normalization statistics
  -> PI0.5 LoRA training
```

## External environment

The current official OpenPI checkout was audited at commit
`15a9616a00943ada6c20a0f158e3adb39df2ccac`. It pins LeRobot to commit
`0cf864870cf29f4738d3ade893e6fd13fbd7cdb5`, whose dataset codebase version is
`v2.1`. Keep this environment separate from the lightweight SLaI runtime:

- Python 3.11 (the official project requires `>=3.11`)
- NumPy `<2.0`
- JAX CUDA 12, Torch `2.7.1`, and the official OpenPI dependency set
- the pinned LeRobot v2.1 checkout/runtime

The SLaI development environment currently uses Python 3.13 and NumPy 2.x. It
is intentionally suitable for contract tests and dry-runs, but is not a valid
PI0.5 training environment. Do not install the full OpenPI stack into it.

Inspect each operation before executing it:

```bash
uv run slai-pi05 convert
uv run slai-pi05 norm
uv run slai-pi05 train --smoke
```

Set `LEROBOT_V21_PYTHON` to the Python executable of a dedicated LeRobot v2.1
environment and set `OPENPI_ROOT` to a maintained OpenPI checkout. Then use
`--execute` for the selected operation. The converter refuses to overwrite an
existing target and never samples an action horizon across episode boundaries.

The physical contract is unchanged from the tested legacy pipeline: policy state is
`tcp_pose[6] + real_joint_state[26]`, and policy action is `tcp_velocity[6] +
wujihand_target[20]`. The model pads actions to 32 dimensions internally; padding is
removed before returning commands.

Project data layout:

```text
data/raw/                    # untouched source captures
data/training/pi05/          # converted LeRobot v2.1 training roots
data/normalization/pi05/     # OpenPI norm stats for those roots
```
